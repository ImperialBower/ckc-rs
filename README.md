[![Build and Test](https://github.com/ImperialBower/ckc-rs/actions/workflows/CI.yaml/badge.svg)](https://github.com/ImperialBower/ckc-rs/actions/workflows/CI.yaml)

[![Rustdocs](https://docs.rs/ckc-rs/badge.svg)](https://docs.rs/ckc-rs/)

A `no_std`, zero-dependency [Cactus Kev](https://suffe.cool/poker/evaluator.html)
poker hand evaluation kernel.

Lookup tables borrowed from Vladislav Supalov's
[pokereval-rs](https://github.com/vsupalov/pokereval-rs), which in turn came from
[Cactus Kev's work in C](https://suffe.cool/poker/code/).

```rust
use ckc_rs::standard52::{Card, Five};

let royal = [
    Card::ACE_SPADES,
    Card::KING_SPADES,
    Card::QUEEN_SPADES,
    Card::JACK_SPADES,
    Card::TEN_SPADES,
];

// 1 is the best possible hand; 7462 is the worst. Lower wins.
assert_eq!(1, Five::eval(royal));
```

## What's here

Everything lives under `ckc_rs::standard52` — the 52-card French deck. The module
is namespaced (and feature-gated) so a future deck family can be added beside it
without disturbing this one.

| Type | Role |
|---|---|
| `Card` | a `u32` newtype in the Cactus Kev bit layout |
| `CardNumber` | the 52 canonical card values as an enum |
| `Rank`, `Suit`, `SuitShift` | the card's components |
| `Five`, `Six`, `Seven` | fixed-size hands |
| `Five::eval` | the headline entry point |
| `HandRanker`, `HandValidator` | evaluate and validate a hand |
| `HandRank`, `HandRankName`, `HandRankClass` | a rank and its human meaning |
| `CkcError` | the crate's error type |

Hands of more than five cards evaluate every five-card subset and return the best:
`Seven` checks 21 permutations, `Six` checks 6.

## The card layout

`Card` is a `u32` variant of Cactus Kev's representation. The variation is that the
suit bit order is inverted, for easier sorting by other libraries.

```txt
+--------+--------+--------+--------+
|mmmbbbbb|bbbbbbbb|SHDCrrrr|xxpppppp|
+--------+--------+--------+--------+

p = prime number of rank (deuce=2,trey=3,four=5,...,ace=41)
r = rank of card (deuce=0,trey=1,four=2,five=3,...,ace=12)
SHDC = suit of card (bit turned on based on suit of card)
b = bit turned on depending on rank of card
m = flags reserved for multiples of the same rank; stripped before evaluation
```

## Features

| Feature | Default | Effect |
|---|---|---|
| `standard52` | ✅ | the 52-card deck and its tables. Without it the crate is empty. |
| `std` | ✅ | implies `alloc`; nothing else at present |
| `alloc` | — | allocating conveniences (`bit_string`, pretty formatters). The evaluator never allocates. |
| `serde` | — | serialization. **Implies `alloc`** — see the note in `Cargo.toml`. |

`--no-default-features` alone builds an empty crate, since `standard52` is itself a
feature. For a `no_std` build you want:

```bash
cargo build --no-default-features --features standard52
```

CI builds that combination for `thumbv7em-none-eabi` and `wasm32-unknown-unknown`,
and asserts the default dependency tree contains exactly one crate: this one.

## Correctness

The evaluator is checked against **all 2,598,960 five-card hands** by
`tests/golden_oracle.rs`, comparing every rank to values generated by the frozen,
published `ckc-rs` 0.1.18. The four lookup tables carry SHA-256 regression guards
(`tests/table_identity.rs`), and an exhaustive C(52,7) sweep over all 133,784,560
seven-card hands is available behind `#[ignore]`.

The golden fixture is excluded from the published package for size; the test skips
when it is genuinely absent and fails if it goes missing from a git checkout.

Invalid hands — duplicates, blanks, or cards carrying multiple-rank flags — return
`NO_HAND_RANK_VALUE` (0) rather than a plausible-looking rank. Note that `Six` and
`Seven` validate per-subset, so a duplicate does not necessarily invalidate the
whole hand; `tests/invalid_hands.rs` pins the difference.
